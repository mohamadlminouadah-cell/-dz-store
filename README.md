# دليل المتجر الإلكتروني الجزائري — التشغيل والنشر خطوة بخطوة

هذا مشروع متجر إلكتروني كامل لبيع سلعك في الجزائر: واجهة عربية (من اليمين إلى اليسار) تعمل على الهاتف والكمبيوتر، سلة وطلب بالدفع عند الاستلام، اختيار الولاية (58) والبلدية (1541) تلقائياً، لوحة إدارة محمية بكلمة مرور، وقاعدة بيانات حقيقية تبقى بياناتها عند تغيير الهاتف أو الجهاز.

## 1. ما الذي بين يديك؟

| المجلد/الملف | ما هو |
|---|---|
| `web/` | المتجر نفسه (ما يراه الزبائن) ولوحة الإدارة في `web/admin/` |
| `web/config.json` | الملف الوحيد الذي تعدّله: رابط Supabase والمفتاح العام |
| `functions/` | يجعل رابط المنتج يظهر باسمه وصورته وسعره عند مشاركته على فيسبوك وواتساب، ويضع اسم متجرك على التطبيق المثبّت (يعمل على Cloudflare Pages) |
| `sql/01_schema.sql` | يُنشئ الجداول والحماية ودوال الطلبات والمخزون |
| `sql/02_seed_locations.sql` | الولايات الـ58 وبلدياتها الـ1541 وأسعار التوصيل المبدئية |
| `sql/03_storage.sql` | مخزن صور المنتجات |
| `sql/04_make_admin.sql` | يجعل بريدك مديراً للمتجر |

**كيف تعمل الأجزاء معاً:** الواجهة (ملفات ثابتة على Cloudflare Pages) تتكلم مع Supabase (قاعدة البيانات وتسجيل الدخول وتخزين الصور). كل قواعد الأمان وحساب الأسعار والمخزون موجودة داخل قاعدة البيانات نفسها، فلا يستطيع زائر تعديل سعر أو قراءة طلبات حتى لو فتح أدوات المتصفح.

## 2. التكلفة (كل شيء مجاني للبداية)

| الخدمة | ما تفعله | الخطة المجانية (حسب مصادر عامة وقت الكتابة) |
|---|---|---|
| Supabase | قاعدة البيانات + الدخول + الصور | 500 ميغابايت قاعدة بيانات، 1 غيغابايت صور، 5 غيغابايت نقل شهرياً |
| Cloudflare Pages | استضافة المتجر برابط عام | 500 عملية نشر شهرياً، وطلبات الدوال تُحسب ضمن حصة Workers المجانية |
| GitHub | تخزين ملفات المشروع | مجاني |

> **تنبيه مهم:** مشاريع Supabase المجانية **تتوقف تلقائياً بعد أسبوع بلا نشاط**. المتجر الذي يستقبل زيارات لن يتوقف عادة، لكن إن تركته أسبوعاً بدون أي زيارة أو دخول فادخل لوحة Supabase واضغط «Restore». تأكد من الأرقام الحالية في supabase.com/pricing لأنها قد تتغير.

**مصاريف اختيارية لاحقاً:** دومين خاص (مثل `mystore.com`) بسعر يختلف حسب المسجّل، وخطة Supabase المدفوعة إذا كبر المتجر كثيراً.

## 3. الخطوة 1 — إنشاء مشروع Supabase

1. افتح **supabase.com** واضغط **Start your project** وسجّل بحساب GitHub أو بريدك.
2. اضغط **New project**، واكتب:
   - **Name:** اسم متجرك (مثال: `my-store`).
   - **Database Password:** كلمة مرور قوية — احفظها في مكان آمن (لن تحتاجها يومياً).
   - **Region:** اختر أقرب منطقة لأوروبا (مثل Frankfurt أو Paris) فهي الأسرع للجزائر.
3. اضغط **Create new project** وانتظر دقيقة أو دقيقتين حتى يجهز.

## 4. الخطوة 2 — تشغيل ملفات SQL (4 ملفات بالترتيب)

لكل ملف افعل التالي:

1. في Supabase من القائمة اليسرى اختر **SQL Editor** ثم **New query**.
2. افتح الملف من مجلد `sql` بأي محرر نصوص (Notepad يكفي)، اضغط `Ctrl + A` ثم `Ctrl + C` لنسخ كل المحتوى.
3. الصقه في خانة الكتابة في Supabase (`Ctrl + V`) واضغط **Run**.
4. يجب أن تظهر رسالة **Success**. إن ظهر خطأ أحمر فصوّره وأرسله لي.

الترتيب:

1. `01_schema.sql`
2. `02_seed_locations.sql` (ملف كبير، قد يستغرق ثواني)
3. `03_storage.sql`
4. `04_make_admin.sql` — **بعد** الخطوة التالية (إنشاء حساب المدير).

> لا تشغّل `01_schema.sql` مرتين على بيانات حقيقية بعد بدء البيع. تشغيله مرة ثانية آمن في الغالب (لا يمسح البيانات)، لكن لا داعي له.

## 5. الخطوة 3 — إنشاء حساب المدير وتأمينه

1. من القائمة اليسرى: **Authentication ← Users ← Add user ← Create new user**.
2. اكتب بريدك وكلمة مرور **قوية** (12 حرفاً فأكثر، فيها أحرف وأرقام ورموز) وفعّل خيار **Auto Confirm User**، ثم **Create user**.
3. ارجع إلى **SQL Editor**، افتح `04_make_admin.sql`، غيّر `ضع_بريدك_هنا@gmail.com` إلى نفس البريد حرفياً، ثم **Run**. يجب أن يظهر صف فيه بريدك.
4. **أوقف التسجيل العام:** من **Authentication** ابحث عن إعدادات تسجيل الدخول (قد تسمّى **Sign In / Providers** أو **Settings**) وأطفئ خيار **Allow new users to sign up**. بهذا لا يستطيع أحد إنشاء حساب غيرك. (حتى لو أنشأ أحد حساباً فلن يصبح مديراً لأن الصلاحية تُمنح فقط عبر الملف 04، لكن إيقافه أنظف.)

**تأمين الحساب:** فعّل التحقق بخطوتين على حسابات Supabase وGitHub وCloudflare، ولا تشارك كلمة المرور مع أحد.

## 6. الخطوة 4 — ربط المتجر بـ Supabase (ملف config.json)

1. في Supabase اضغط **Project Settings** (رمز الترس) ثم **API** (أو **Data API / API Keys** حسب النسخة).
2. انسخ قيمتين:
   - **Project URL** — شكلها `https://xxxxxxxx.supabase.co`
   - **anon public key** (يسمّى أحياناً **Publishable key**) — نص طويل.
3. افتح `web/config.json` وعدّله هكذا:

```json
{
  "supabaseUrl": "https://xxxxxxxx.supabase.co",
  "supabaseAnonKey": "الصق_المفتاح_الطويل_هنا",
  "shareViaFunction": true
}
```

> **أمان:** المفتاح `anon` مصمم ليكون علنياً، وحمايتك الحقيقية هي قواعد RLS في قاعدة البيانات. أما المفتاح المسمى **service_role** (أو secret) فهو سري جداً: **لا تضعه في أي ملف إطلاقاً**. المتجر لا يحتاجه.

> اترك `"shareViaFunction": true` إذا نشرت على Cloudflare Pages (الموصى به). غيّره إلى `false` فقط إذا استعملت GitHub Pages.

## 7. الخطوة 5 — رفع المشروع إلى GitHub

1. فك ضغط المشروع على الكمبيوتر. تأكد أن `config.json` معدّل.
2. في **github.com** اضغط **New repository**، سمّه (مثال: `my-store`)، واجعله **Private** (خاص) أو Public، ثم **Create repository**.
3. اضغط **uploading an existing file** (أو **Add file ← Upload files**).
4. اسحب **كل محتويات** المجلد (المجلدات `web` و`functions` و`sql` وملف `README.md`) إلى الصفحة. يجب أن تبقى المجلدات في جذر المستودع كما هي.
5. اضغط **Commit changes**.

> يعمل سحب المجلدات من متصفح الكمبيوتر. من الهاتف يصعب رفع المجلدات، فاستعمل الكمبيوتر لهذه الخطوة.

## 8. الخطوة 6 — النشر على Cloudflare Pages (موصى به)

1. سجّل في **dash.cloudflare.com** (مجاني).
2. من القائمة: **Workers & Pages** ثم **Create** ثم **Pages** ثم **Connect to Git**. (إن لم تجد خيار Pages واضحاً فابحث عن رابط صغير مثل «Looking to deploy Pages? Get started». واجهة Cloudflare تتغير أحياناً.)
3. اربط حسابك بـ GitHub واختر مستودع المتجر.
4. إعدادات البناء:
   - **Framework preset:** None
   - **Build command:** اتركه فارغاً
   - **Build output directory:** `web`
5. اضغط **Save and Deploy**. بعد دقيقة تحصل على رابط مثل `https://my-store.pages.dev` — هذا رابط متجرك العام الثابت.

**لتحديث أي ملف لاحقاً:** افتحه في GitHub، اضغط رمز القلم، عدّل، ثم **Commit changes**. يُعاد النشر تلقائياً خلال دقيقة. (أسعار المنتجات والصور والطلبات لا تحتاج هذا: تُدار من اللوحة مباشرة.)

### بديل: GitHub Pages (بدون معاينة الروابط)
1. أعد تسمية المجلد `web` إلى `docs` قبل الرفع، وغيّر `shareViaFunction` إلى `false`.
2. في المستودع: **Settings ← Pages ← Branch: main / folder: /docs ← Save**.
3. عيب هذا الخيار: عند مشاركة رابط منتج لن تظهر صورته وسعره في معاينة فيسبوك (يظهر اسم المتجر فقط)، لأن GitHub Pages لا يشغّل الدوال.

## 9. الخطوة 7 — أول دخول وإعداد المتجر

افتح `https://رابط-متجرك/admin/` وسجّل الدخول ببريدك وكلمة مرورك. نفّذ بالترتيب:

1. **الإعدادات:** اسم المتجر، الشعار، رقم الهاتف، رقم واتساب (اكتبه كما هو `0550123456` ويتحول تلقائياً)، روابط فيسبوك/إنستغرام/تيك توك، اللون، شريط إعلان اختياري. اضغط **حفظ الإعدادات**.
2. **التوصيل:** ⚠️ أسعار التوصيل المبدئية **قيم افتراضية مني وليست أسعاراً حقيقية** (600 دج للمنزل و400 دج للمكتب لكل الولايات). عدّلها حسب شركة التوصيل التي تتعامل معها:
   - «تطبيق سعر موحّد على كل الولايات» ثم عدّل الولايات المختلفة واحدة واحدة.
   - اترك خانة المكتب فارغة لإلغاء الاستلام من المكتب في ولاية.
   - أطفئ «التوصيل مفعّل» لولاية لا توصّل إليها.
   - زر **البلديات** يسمح بسعر خاص لبلدية معينة.
   - التوصيل المجاني: اكتب حداً مثل 8000 دج في «التوصيل المجاني للطلبات الكبيرة» (0 = معطّل). وسعر 0 دج لولاية = توصيل مجاني لها.
3. **التصنيفات:** أضف تصنيفاتك (ملابس، أحذية…).
4. **المنتجات:** أضف أول منتج (انظر القسم التالي).
5. افتح المتجر من «عرض المتجر» واطلب طلباً تجريبياً، ثم احذفه من اللوحة (زر «حذف الطلب» يعيد الكمية للمخزون).

## 10. الاستعمال اليومي

### إضافة منتج
المنتجات ← **+ إضافة منتج** ← اكتب الاسم والوصف، ارفع الصور (حتى عدة صور؛ تُضغط تلقائياً لتكون سريعة، والأولى هي الأساسية)، اكتب سعر البيع، وسعر الشراء (لا يراه الزبون)، والكمية، والتصنيف. اضغط **إضافة المنتج**.

- **تخفيض:** اكتب «السعر القديم» أكبر من سعر البيع، فيظهر مشطوباً مع نسبة التخفيض.
- **ألوان/مقاسات:** اكتبها مفصولة بفاصلة (`S، M، L`). الكمية واحدة للمنتج كله وليست لكل مقاس.
- **الحالة:** «متاح»، أو «غير متاح» (يظهر ولا يُطلب)، أو «مخفي» (لا يظهر للزبائن). «نفد من المخزون» تظهر تلقائياً عندما تصل الكمية صفراً.
- **مميز:** يظهر في أعلى الصفحة الرئيسية.
- **تغيير السعر أو الصورة:** زر **تعديل** على المنتج. **نسخ** ينشئ منتجاً مشابهاً بسرعة.

### الطلبات والمخزون (قاعدة واضحة تمنع الحساب المزدوج)
| حالة الطلب | وضع الكمية |
|---|---|
| جديد / قيد التأكيد | **محجوزة** (لا تُباع لشخص آخر، لكن المخزون الفعلي لم ينقص) |
| تم التأكيد / قيد التجهيز / تم الشحن / تم التسليم | **مخصومة** من المخزون (مرة واحدة فقط مهما غيّرت الحالات) |
| ملغى / مرتجع | **تعود** للمخزون |

- الزبون لا يستطيع طلب أكثر من المتاح (المخزون − المحجوز).
- زر الإجراء السريع على بطاقة الطلب ينقل الطلب للخطوة التالية (تأكيد ← تجهيز ← شحن ← تسليم).
- إعادة فتح طلب ملغى تفشل برسالة إذا لم تعد الكمية متوفرة.
- داخل الطلب: اتصال، واتساب، ملاحظاتك الخاصة، **طباعة** (ورقة بالمبلغ المطلوب عند الاستلام)، وتغيير الحالة.
- البحث بالرقم أو الاسم أو الهاتف، وتصدير **Excel/CSV** من أعلى صفحة الطلبات.

### المبيعات والأرباح (مثال بأرقام)
المبيعات تحسب الطلبات **«تم التسليم» فقط**، وبدون رسوم التوصيل؛ الملغى والمرتجع والقيد التنفيذ لا يُحسب.

مثال: قميص سعر بيعه 2500 دج وشراؤه 1400 دج، سُلّم منه 2:
- المبيعات = 2 × 2500 = **5 000 دج**
- التكلفة = 2 × 1400 = **2 800 دج**
- الربح = 5000 − 2800 = **2 200 دج**

إذا لم تُدخل «سعر الشراء» لمنتج، تظهر تنبيهات أن الربح غير دقيق. التنبيه على المخزون المنخفض يظهر في «الرئيسية» (الحد يتغير من الإعدادات).

### كوبونات الخصم
الكوبونات ← أنشئ رمزاً (نسبة % أو مبلغ ثابت) بحد أدنى للطلب وعدد استعمالات وتاريخ انتهاء اختياريين. يكتبه الزبون في صفحة الطلب.

## 11. نشر رابط المتجر على مواقع التواصل

- **رابط المتجر:** `https://رابط-متجرك` — ضعه في وصف صفحتك على فيسبوك، وفي السيرة الذاتية (Bio) على إنستغرام وتيك توك، وأرسله في واتساب وماسنجر.
- **رابط منتج:** افتح المنتج في المتجر واضغط **نسخ الرابط** (أو أزرار واتساب/فيسبوك/ماسنجر). الرابط يكون بصيغة `…/p/رقم-المنتج` ويعرض اسم المنتج وصورته وسعره في المعاينة.
- **إنستغرام وتيك توك** لا يوفران رابط مشاركة مباشراً: استعمل زر **مشاركة** (يفتح قائمة المشاركة في الهاتف) أو انسخ الرابط للـBio أو ملصق الرابط في القصص.
- **إذا لم تتحدث معاينة فيسبوك** بعد تغيير صورة أو سعر، افتح أداة **Sharing Debugger** من فيسبوك والصق الرابط واضغط **Scrape Again**؛ فيسبوك يحتفظ بنسخة قديمة مؤقتاً.

## 12. ربط دومين خاص (اختياري)

1. اشترِ دومين من أي مسجّل.
2. في Cloudflare: مشروع الـPages ← **Custom domains ← Set up a custom domain** واكتب الدومين.
3. اتبع التعليمات (غالباً سجل **CNAME** يشير إلى `my-store.pages.dev`) عند مسجّل الدومين، وانتظر دقائق إلى ساعات.
4. تتحول روابط المشاركة تلقائياً لتستعمل الدومين الجديد.

## 13. النسخ الاحتياطي والاستعادة

- **كل أسبوع:** اللوحة ← **نسخ احتياطي** ← **تنزيل النسخة الاحتياطية**. يُحفظ ملف JSON فيه المنتجات والتصنيفات والتوصيل والكوبونات والإعدادات والطلبات (الصور تبقى في Supabase والملف يحفظ روابطها). احفظه في Google Drive أو على هاتفك.
- **الاستعادة:** **اختيار ملف واستعادة** ← اختر الملف. الاستعادة **تدمج** النسخة مع الموجود: تُرجع ما حُذف وتعيد القيم القديمة للموجود، ولا تحذف ما أضفته بعد النسخة.
- **تصدير الطلبات إلى Excel** متاح من نفس الصفحة.
- لا تعتمد على نسخ Supabase التلقائية في الخطة المجانية (حسب علمي لا تتيح استعادة تلقائية)، فنسختك اليدوية هي الأمان الحقيقي.

## 14. قائمة الأمان

- كلمة مرور المدير قوية وفريدة، والتحقق بخطوتين على GitHub وSupabase وCloudflare.
- التسجيل العام في Supabase مطفأ.
- لا تضع مفتاح `service_role` في أي ملف.
- كلمات المرور لا تُخزَّن في المتجر أبداً: يديرها نظام الدخول في Supabase بتشفير.
- كل قراءة للطلبات وتعديل للمنتجات محمي في قاعدة البيانات (RLS)، والتحقق من الاسم والهاتف والكميات والأسعار يتم **في الخادم** وليس في الواجهة فقط. الزبون لا يرسل أسعاراً، الخادم يحسبها من المنتجات.
- حماية من البوتات: حقل مخفي، وحد 5 طلبات في الساعة لنفس رقم الهاتف.
- لتغيير كلمة المرور: اللوحة ← الإعدادات ← تغيير كلمة المرور. ولو نسيتها: Supabase ← Authentication ← Users ← اختر حسابك ← إرسال رابط استعادة.

## 15. حل المشاكل الشائعة

| المشكلة | الحل |
|---|---|
| المتجر يعرض «المتجر غير مُعدّ بعد» | `config.json` ما زال فيه القيم الافتراضية أو الرابط خاطئ. عدّله وأعد الرفع. |
| صفحة المتجر فارغة أو «تعذّر تحميل المتجر» | تأكد أن ملفي `01` و`02` نُفذا بنجاح، وأن مشروع Supabase غير متوقف (Restore). |
| اللوحة تقول «هذا الحساب ليس مديراً» | شغّل `04_make_admin.sql` بنفس البريد المسجّل في Authentication تماماً. |
| رفع الصورة يفشل | شغّل `03_storage.sql`، وتأكد أنك مسجّل كمدير. |
| «ليست لديك صلاحية لهذا الإجراء» | انتهت الجلسة؛ سجّل الخروج ثم الدخول. |
| منتج لا يظهر للزبائن | حالته «مخفي»، أو لم تحفظه، أو غيّرت تصنيفاً. افتحه في المنتجات. |
| زبون لا يجد ولايته | عطّلت التوصيل لها في صفحة التوصيل. |
| «أرسلت عدة طلبات خلال وقت قصير» | حماية: 5 طلبات/ساعة لنفس الرقم. تنتظر ساعة. |

## 16. أين أعدّل على المتجر؟

**أغلب التعديلات من لوحة الإدارة بدون أي كود** (`رابط-متجرك/admin/`). أما تعديل الشكل والنصوص الثابتة فمن ملفات المشروع في GitHub: افتح الملف ← رمز القلم ← عدّل ← **Commit changes** ← يتحدث المتجر تلقائياً خلال دقيقة.

| تريد تغيير… | أين؟ |
|---|---|
| اسم المتجر، الشعار، الهاتف، واتساب، روابط التواصل، لون المتجر، شريط الإعلان، إيقاف الطلبات | اللوحة ← **الإعدادات** |
| المنتجات والأسعار والصور والكميات والتخفيضات | اللوحة ← **المنتجات** |
| أسعار التوصيل والتوصيل المجاني | اللوحة ← **التوصيل** |
| التصنيفات والكوبونات | اللوحة ← **التصنيفات / الكوبونات** |
| ربط Supabase | `web/config.json` |
| الألوان العامة والخطوط والأحجام وشكل البطاقات | `web/css/base.css` (أعلى الملف: المتغيرات `--ink` و`--ground` و`--f-display`) و`web/css/store.css` |
| نصوص ثابتة مثل «تتبّع طلبي» وعناوين الصفحة | `web/index.html` |
| رسائل المتجر والأزرار (مثل «أضف إلى السلة» و«إتمام الطلب») | `web/js/store.js` |
| رسائل الأخطاء بالعربية | `web/js/common.js` |
| أيقونة التطبيق | استبدل الصور في `web/icons/` بنفس الأسماء والمقاسات (192 و512) |
| أي تعديل في التصميم لا تعرف كيف تنفذه | اطلبه مني وأعدّل الملف لك |

> لا تغيّر ملفات `sql/` بعد بدء البيع. وأي تغيير في قاعدة البيانات اسألني قبله.

## 17. تثبيت المتجر كتطبيق، وهل يعمل على الحاسوب؟

المتجر **موقع ويب يعمل على أي جهاز**: هاتف أندرويد، آيفون، حاسوب (Chrome وEdge وFirefox وSafari). ويمكن تثبيته كتطبيق (تقنية PWA)، فتصبح له أيقونة على الشاشة ويفتح في نافذة مستقلة بدون شريط المتصفح. هذا ليس تطبيقاً في Google Play أو App Store، وهو يحتاج اتصالاً بالإنترنت لعرض المنتجات وإرسال الطلبات.

- **أندرويد (Chrome):** افتح المتجر ← اضغط زر **تثبيت المتجر كتطبيق** أسفل الصفحة (أو القائمة ⋮ ← **تثبيت التطبيق / Add to Home screen**).
- **آيفون (Safari فقط):** زر المشاركة ⬆ ← **إضافة إلى الشاشة الرئيسية**.
- **الحاسوب (Chrome/Edge):** أيقونة التثبيت في شريط العنوان، أو القائمة ← **Install**.
- **تطبيق الإدارة:** افتح `رابط-متجرك/admin/` ثم ثبّته بنفس الطريقة، فتصبح لك أيقونة «الإدارة» لمتابعة الطلبات من هاتفك.
- يظهر اسم التطبيق المثبّت ولونه من إعدادات المتجر عند النشر على Cloudflare Pages (على GitHub Pages يظهر الاسم العام «المتجر»).
- **نشره على Google Play** ممكن لاحقاً بتغليف الموقع (TWA)، لكنه يحتاج حساب مطوّر مدفوعاً وإجراءات إضافية؛ لا حاجة له في البداية.

## 18. هل أستطيع بيعه للناس؟

**نعم، لكن بالطريقة الصحيحة.** هذا المشروع **متجر واحد لكل عميل** وليس منصة واحدة تستضيف آلاف المتاجر. أي أن كل عميل يحصل على نسخته: مشروع Supabase خاص به، وموقع خاص به، وبياناته ومنتجاته منفصلة عن غيره.

**طريقة العمل مع كل عميل (حوالي ساعتين إلى ثلاث ساعات بعد أن تتقن الخطوات):**
1. تنشئ **حسابات باسم العميل** (Supabase وGitHub وCloudflare) أو تطلب منه إنشاءها وتضيف نفسك كمساعد، حتى يملك متجره ولا يتوقف بتوقفك.
2. تنسخ المشروع وتشغّل ملفات SQL الأربعة، وتضع مفاتيحه في `config.json`، وتنشر.
3. تدخل الإعدادات: اسم المتجر وشعاره وهاتفه وألوانه وأسعار التوصيل التي يعمل بها فعلاً.
4. تدرّبه على اللوحة (إضافة منتج، تأكيد طلب، النسخ الاحتياطي) وتسلّمه الدليل.

**كيف تربح:** رسوم تركيب لمرة واحدة، ثم اشتراك شهري اختياري للدعم والتعديلات. حدّد أنت الأسعار حسب سوقك ومستوى العميل، وراجع ما يعرضه المنافسون في مدينتك.

**قبل أن تبيع لأحد (مهم):**
- **جرّب أولاً على متجر حقيقي لك** حتى يعمل كل شيء على Supabase الفعلي (راجع القسم 19: لم أستطع اختبار Supabase الحقيقي هنا). لا تبع قبل أن تكتمل تجربتك بنفسك.
- **الاستضافة المجانية للتجربة:** مشاريع Supabase المجانية تتوقف بعد أسبوع بلا نشاط. للعميل الجاد الذي يعتمد على متجره يجب أن ترفع مشروعه إلى خطة مدفوعة (تحقق من السعر الحالي في supabase.com/pricing)، ويدفعها هو أو تضيفها لاشتراكه.
- **اتفاق مكتوب بسيط** مع كل عميل: ما الذي تقدمه، وما الذي لا يشمله (مثل شركات التوصيل أو الدفع الإلكتروني)، ومدة الدعم، ومن يملك الحسابات.
- **لا تعد بما لم يُبنَ:** المتجر لا يتضمن دفعاً إلكترونياً (CIB/الذهبية) ولا ربطاً تلقائياً بشركات التوصيل ولا خيار لغتين. هذه إضافات تُبنى لاحقاً مقابل رسوم.
- **بيانات الولايات والبلديات** من مستودع مفتوح بدون ملف رخصة صريح (راجع القسم 19).
- **لبيع المشروع نفسه (الكود) لشخص آخر** ليبيعه هو: ممكن، لكن اكتب ما يحق له فعله بالنسخة (استعمال لمتجره فقط أم إعادة بيعه).

**ماذا لو أردت منصة واحدة تستضيف عدة متاجر باشتراك؟** هذا مشروع أكبر (حسابات تجار، فصل بيانات كل متجر، دفع اشتراكات)، ولا أنصح به قبل أن تنجح مع 5 إلى 10 عملاء بالطريقة الحالية.

## 19. ما اختبرته وما لم أستطع اختباره (بصراحة)

**اختُبر فعلاً:**
- قاعدة البيانات على Postgres 16 حقيقي مع أدوار وقواعد RLS مماثلة لـSupabase: نحو 75 فحصاً (صلاحيات الزائر والمدير، حساب التوصيل والكوبون، حجز المخزون وخصمه وإرجاعه دون ازدواج، الإحصاءات، حذف الطلب).
- الواجهة في متصفح Chromium حقيقي: رحلة الزبون كاملة (33 فحصاً) ولوحة الإدارة كاملة (37 فحصاً: الطلبات، المنتجات مع رفع الصور، التوصيل، الكوبونات، الإعدادات، التصدير، النسخ الاحتياطي والاستعادة).
- عدد الولايات 58 والبلديات 1541 وكل بلدية تتبع ولايتها، والقائمة تتغير تلقائياً دون تداخل.

**لم أستطع اختباره هنا:**
- مكتبة `supabase-js` الحقيقية وتسجيل الدخول وتخزين الصور على Supabase الفعلي (لا يتوفر لي الوصول إليها)؛ اختبرت الواجهة عبر بديل يرسل نفس العمليات إلى قاعدة بيانات حقيقية. قد تظهر ملاحظة صغيرة عند أول تشغيل على Supabase الحقيقي؛ أرسل لي نص الخطأ وأصلحه.
- النشر الفعلي على Cloudflare Pages ومعاينة فيسبوك الحقيقية (اختبرت منطق الدالة فقط).
- تجربة على هواتف حقيقية (اختبرت بحجم شاشة هاتف في المتصفح).
- التثبيت كتطبيق على جهاز فعلي (اختبرت أن الملف التعريفي والأيقونات وعامل الخدمة يعملان، وأن الواجهة تفتح عند انقطاع الاتصال).

**ملاحظات:** بيانات الولايات والبلديات من مستودع مفتوح (`algeria-cities` على GitHub، مبني على بيانات وزارة الداخلية)، ولم أجد فيه ملف رخصة صريحاً؛ هي بيانات إدارية عامة. وقد تتغير تقسيمات إدارية مستقبلاً: يمكن تعديل جدول `communes` من Supabase.
